# 주간 결과 브리핑 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 기존 주간 처리를 한 번 실행한 뒤 실제 상태 변화를 한 장으로 전달하고 최근26주를 읽기 전용으로 재열람한다.

**Architecture:** `index.html` 안에 순수 스냅샷·차이 계산·렌더 함수를 추가한다. 행동 직전/직후/주간 종료 상태와 기존 경기 정산 결과를 관찰하여 저장하며 보상 함수를 다시 호출하지 않는다. 중요 컷씬과 경기 선택은 기존 흐름을 유지한다.

**Tech Stack:** Vanilla HTML/CSS/ES6+, Node VM 회귀 검사, Playwright CLI.

**Spec:** `docs/reports/UI_UX_RENEWAL_AND_NEXT_PLAN_2026-11-03.md`의 1순위 주간 결과 브리핑. 사용자 구현 승인: 현재 요청.

## Global Constraints

- 기존 폴더·단일 파일·PWA 구조 유지. 기존 미커밋 변경 보존.
- 기존 세이브 키·자원·성장·난수·주간 데이트/SNS 제한 유지. 선택 필드 `weeklyBriefingHistory`는 누락 시 빈 배열.
- 새 기록은 최근26개, 같은 연차/주차는 중복 저장하지 않는다. 구버전 주간 결과를 추정해서 생성하지 않는다.
- 브리핑은 서사 대사/이미지를 재생하지 않는다. 표시 문자열 escape, 보상/경기 재실행 없음.
- 버전2.4.0/16 동기화, 커밋·push·배포·APK 재빌드 없음.

## Review Focus

- 취소/무효 일정/연타는 주차나 기록을 추가하지 않는다.
- 시즌 경계·자연 은퇴·새 커리어에서 기록의 주차와 소유 선수가 섞이지 않는다.
- 여러 경기·우승/콜업·인연 변화가 최종 저장 수치와 일치한다.
- 재로드/재열람/닫기는 재정산하지 않는다. 손상된 선택 메타데이터는 기존 세이브를 막지 않는다.
- 모바일320/390px, 데스크톱1100px의 긴 수치/기록에서도 스크롤·닫기 접근이 가능하다.

## 실행 기록

- 설계 결정: 최근26주 보존은 이번 구현의 범위 선택이다. 기존 상태가 없는 과거 주는 복원하지 않는다.
- 기존 작업 중인 폴더를 계속 사용하며 이번 기능을 임의로 커밋하지 않는다.

- 완료: 기존70개+브리핑14개=84개 통과. 기준 비교624주 일치. 브라우저/파이프라인/구문/버전 검사 및 독립 리뷰 완료.
- Ruling: LP 갱신의 동시 인연 장면이 요약을 덮는 경계를 재현해 장면 큐와 해금 Promise 대기를 추가했다. 번아웃 LP 차감도 별도 대기한다. 수치 공식은 유지하며 정산 비교624주로 확인했다.
- Ruling: 부분 손상된 rank/스탯/누계 기록은 선택 메타데이터 검증에서 제외하여 선수 세이브와 정상 기록의 재열람을 보존한다.
